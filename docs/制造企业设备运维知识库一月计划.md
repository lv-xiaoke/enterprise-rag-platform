# 制造企业设备运维知识库：一个月实施计划

## 1. 月度目标

在现有 Mini RAG 后端上，完成一个可运行、可评测、可演示的“制造企业设备运维知识库”。本月只做教学演示，不接入真实企业数据或生产系统。

月底需要交付：

- 一套来源清楚、结构统一的虚构运维资料。
- 一个支持多文档、持久化、版本过滤和来源引用的 RAG 后端。
- 一个简单的文档管理与问答页面。
- 一套固定评测题及评测报告。
- README、架构图、演示脚本和演示视频。

## 2. 本月范围

### 必须完成

- 使用 PostgreSQL + pgvector 保存文档、Chunk、向量和元数据。
- 支持文档上传、列表、处理状态、停用和重新索引。
- 检索时只使用指定知识库中的当前有效文档。
- 回答引用到文档名称、版本、页码和原文片段。
- 资料不足时明确拒答，不编造维修步骤。
- 使用固定问题集比较至少两组检索参数。
- 使用 Docker Compose 启动主要服务，并提供复现说明。

### 有时间再做

- PostgreSQL 关键词检索与向量检索组成混合检索。
- 相邻 Chunk 合并或简单 Reranker。
- 问答反馈、耗时统计和未回答问题统计。

这些功能只有在基线评测暴露出明确问题时才加入，不为增加技术名词而增加功能。

### 本月不做

- 真实工厂数据和生产系统对接。
- OCR、图片理解和复杂表格解析。
- 多角色权限、完整多租户和 Celery 任务系统。
- Kubernetes、复杂微服务和商业级前端。
- 自动下发维修指令或控制设备的 Agent。

## 3. 数据集设计

为了控制工作量，第一版只覆盖三类设备：

| 设备类型 | 虚构资产 | 主要知识 |
| --- | --- | --- |
| 螺杆式空气压缩机 | AC-01、AC-02 | 高温、压力不足、滤芯、润滑、点检 |
| 离心泵 | P-01、P-02 | 汽蚀、泄漏、振动、密封、启停 |
| 皮带输送机 | CV-01、CV-02 | 跑偏、打滑、异响、张紧、急停 |

数控机床涉及更独立的故障体系，本月不纳入，后续再扩展。

### 资料规模

计划制作 12～16 份文档和约 20 条虚构维修工单：

- 企业与数据说明 1 份。
- 设备台账 1 份。
- 通用安全制度 2 份。
- 每类设备的操作/点检规程、故障指南、保养计划各 1 份。
- 版本变更通知 2 份，用于测试新旧版本过滤。
- 维修工单约 20 条，覆盖常见故障和重复故障。

全部虚构内容标记为 `synthetic / demo`。公开资料只用于提炼知识点，并在 `source_registry.csv` 中记录标题、来源、URL、访问日期和许可说明；未经许可的原始手册不提交到仓库。

### 核心元数据

每份文档至少保留：

```text
knowledge_base_id
document_id
title
document_type
equipment_type
equipment_ids
version
effective_date
status
page
chunk_id
```

`status` 至少包括 `draft`、`active`、`inactive`。检索默认只使用 `active` 文档。

## 4. 四周计划

### 第一周：准备可信数据和项目骨架

**本周目标**

明确知识库边界，完成首版资料，并准备数据库环境。第一周不追求大量写代码，重点是让后续的数据表、过滤条件和评测都有明确依据。

**本周任务**

- 确定虚构企业、三类设备、典型问题和安全边界。
- 建立资料目录、命名规则、文档模板和来源登记表。
- 编写设备台账、安全制度、运维规程、故障指南和保养计划。
- 生成约 20 条虚构维修工单，并检查设备编号、时间和故障原因是否一致。
- 列出 30 道评测题的题目骨架。
- 启动 PostgreSQL + pgvector 的 Docker Compose 环境。

**本周产出**

- 数据集 v0.1。
- `source_registry.csv` 和数据使用说明。
- 30 道评测题骨架。
- 可启动的数据库环境。

**验收标准**

- 任意抽查 5 份文档，都能说明设备类型、版本、状态和来源。
- 同一设备编号在台账、规程和工单中含义一致。
- 至少 10 道题能在现有资料中找到明确答案。
- 仓库中没有真实敏感数据或不允许重新发布的资料。

### 第二周：完成多文档持久化

**本周目标**

把“单 PDF + 内存 FAISS”升级为服务重启后仍可使用的多文档知识库。

**本周任务**

- 设计知识库、文档、文档版本和 Chunk 数据表。
- 接入 SQLAlchemy、Alembic、PostgreSQL 和 pgvector。
- 保存 Chunk 文本、向量、页码及业务元数据。
- 实现文档上传、列表、详情、停用和重新索引。
- 增加 `pending`、`processing`、`completed`、`failed` 处理状态。
- 检索时按知识库、设备类型和 `active` 版本过滤。
- 补充迁移、接口和服务重启测试。

**本周产出**

- 数据库模型与迁移脚本。
- 多文档入库和检索 API。
- 文档生命周期管理 API。
- 最小化自动测试。

**验收标准**

- 连续上传至少 5 份文档后，可以跨文档检索。
- 重启服务后，无需重新上传即可继续问答。
- 停用文档后，新回答不再引用它。
- 某份文档处理失败时，不影响已经可用的文档。

### 第三周：做好引用、拒答和评测

**本周目标**

让系统不仅能回答，还能说明依据，并在没有依据时停止回答。

**本周任务**

- 优化切块，保留标题、设备、版本和页码。
- 建立向量检索基线，固定 Chunk 大小、Top-k 和阈值。
- 返回文档名、版本、页码、Chunk 和原文片段。
- 设置无答案阈值和安全提示，避免生成无依据的维修步骤。
- 完成 30 道题的标准答案和证据标注。
- 比较至少两组检索参数，记录结果和失败案例。
- 只针对主要失败原因做一次优化；必要时再加入混合检索。

**评测题构成**

| 类型     |  数量 | 主要检查内容         |
| ------ | --: | -------------- |
| 单文档事实题 |   8 | 参数、规定能否正确召回    |
| 操作流程题  |   6 | 步骤和顺序是否完整      |
| 故障诊断题  |   6 | 症状、原因和检查顺序是否对应 |
| 跨文档题   |   4 | 能否结合台账、规程和工单   |
| 版本题    |   3 | 是否排除旧版本        |
| 无答案题   |   3 | 是否正确拒答         |

记录 Recall@K、引用正确率、拒答正确率和端到端延迟。MRR 可选，不作为本月硬性要求。

**本周产出**

- 30 道固定评测题及证据标注。
- 基线与优化后的对照结果。
- 引用和拒答能力。
- 至少 5 个失败案例及原因分析。

**验收标准**

- 随机抽查 10 个可回答问题，引用能定位到原文。
- 已停用的旧版本不会出现在引用中。
- 无答案问题不会生成看似合理的维修步骤。
- 评测脚本可重复运行，结果中保存参数和运行时间。

### 第四周：完成页面、文档和演示

**本周目标**

把后端整理成别人能使用、复现和快速理解的项目作品。

**本周任务**

- 制作轻量文档管理页：上传、列表、状态、停用。
- 制作问答页：问题输入、回答、引用卡片和原文查看。
- 加入加载状态、错误提示、空状态和预设问题。
- 完善健康检查、日志和 Docker Compose 启动流程。
- 编写 README、架构图、数据说明、评测报告和已知限制。
- 完成 3 分钟演示脚本，进行至少两次完整彩排。
- 只修复影响安装、入库、问答和演示的阻塞问题。

**固定演示流程**

```text
上传新版规程
→ 查看处理状态
→ 提问并核对版本、页码和原文
→ 停用旧版
→ 再次提问，确认旧版不再参与检索
→ 提出无答案问题，确认系统拒答
```

**本周产出**

- 可演示的管理页和问答页。
- Docker Compose 与复现说明。
- README、架构图、数据说明和评测报告。
- 3 分钟演示视频或录屏。

**验收标准**

- 按照 README 能在新环境启动并导入演示数据。
- 固定演示流程连续运行两次，无阻塞错误。
- 页面和视频中不出现 API Key、本地隐私路径或账户信息。
- README 和视频中的指标都能在评测结果中找到依据。

## 5. B 站内容安排

视频不再按开发天数拆分，改为每周一条总结，加一条最终演示，共 5 条：

1. 项目范围、设备资料和元数据如何设计。
2. 从单 PDF Demo 升级为 PostgreSQL + pgvector 多文档知识库。
3. 如何评测引用、版本过滤和拒答能力。
4. 如何把 RAG 后端整理成可复现的演示项目。
5. 最终演示：一个可追溯、可评测的设备运维知识库。

每条只讲一个问题，包含：业务问题、关键设计、一次真实运行、一个踩坑或失败案例。视频长度控制在 6～10 分钟，开发过程中顺手保留素材，周末集中整理，不单独占用大量开发时间。

## 6. 月底完成标准

项目满足以下条件即可结束，不继续追加功能：

- 数据：三类设备资料完整，来源与虚构标记清楚，内容无明显矛盾。
- 系统：支持多文档、持久化、状态管理和当前版本过滤。
- 回答：引用可追溯，无资料时能拒答。
- 评测：30 道固定问题可重复运行，并有一次前后对照实验。
- 展示：页面可用，README 可复现，演示流程可稳定运行。

## 7. 进度落后时如何取舍

按以下顺序缩减工作量：

1. 不做 Reranker、混合检索和统计功能。
2. 页面只保留文档列表、问答和引用查看。
3. 视频只保留第三周评测总结和最终演示。
4. 文档可减少到 10～12 份，维修工单可减少到 15 条。

不能省略：多文档持久化、版本过滤、来源引用、拒答、固定评测和复现说明。它们是本项目区别于普通“上传 PDF 聊天 Demo”的核心。
