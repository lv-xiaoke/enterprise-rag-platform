# AI 应用工程师：项目意义与岗位能力

记录时间：2026-08-26

## 问题

> 我现在非常好奇，我做这些项目有意义吗？我去做这些项目的升级时，其实很多地方都是用 AI 帮我做的。对于现在工作的真实环境来说，他们真正在做什么，或者他们需要哪方面的能力？主要针对 AI 应用工程师这个岗位。

## 回答

有意义，而且方向没有走错。真正需要警惕的不是“代码用了 AI”，而是：项目完成了，但能力没有留在自己身上。

从当前项目的 README 和核心代码来看，可以比较诚实地评价为：

| 评价角度 | 当前水平 |
| --- | --- |
| 学习项目 | 7/10，完整走过了一次 RAG 链路 |
| 校招作品 | 5～6/10，可以写进简历，但还不够突出 |
| 企业生产系统 | 2～3/10，仍然是单机 Demo |

目前已经不只是“调用一次大模型 API”。项目实际覆盖了 FastAPI、异步 LLM 调用、PDF 解析、Chunk、Embedding、FAISS、来源引用、异常处理、SQLite、Docker，以及 Top-1/Top-3 对照评估。这些都是真实的积累。

但当前系统只有单 PDF、内存索引、全局状态和小型人工评测，还没有多用户、权限、异步任务、持久化、自动化测试和可观测性。因此，企业不会只因为这个项目就认定开发者已经可以负责生产系统。

## 企业中的 AI 应用工程师在做什么

现实工作通常不是每天研究 Transformer，也不是不停更换 Prompt，更多是在做下面这些事情。

### 1. 把模糊的业务需求变成可以实现的 AI 流程

例如，“做一个售后助手”需要进一步拆解成知识检索、工单查询、工具调用、权限控制、拒答机制和人工接管。

### 2. 处理复杂而且不整洁的数据

包括 PDF、Word、Excel、扫描件、表格、旧版本制度、重复文档、错误编码，以及文档之间的权限关系。

### 3. 优化 RAG 效果

需要处理 Chunk、Embedding、关键词与向量混合检索、metadata filter、reranker、引用和无答案拒答，并针对失败案例反复实验。

### 4. 开发正常的后端系统

包括 API、数据库、Redis、异步任务、认证、限流、重试、并发、日志、Docker 和 CI/CD。很多时候，AI 应用工程师首先需要是一名合格的后端工程师。

### 5. 建立评测，而不是凭感觉判断效果

常见指标包括 Recall@K、MRR、引用正确率、拒答正确率、端到端成功率、延迟、Token 成本和回归测试结果。

### 6. 处理上线后的问题

例如：

- 模型超时后怎么办？
- 文档更新后如何重新索引？
- 如何避免不同企业之间的数据泄漏？
- 模型调用费用突然上升怎么办？
- 模型输出不稳定时怎样降级和兜底？

近期岗位描述也体现了这一点：校招岗位已经要求文档处理、知识库建设、检索调优和 FastAPI 小项目；更成熟的岗位则进一步要求权限控制、失败兜底、评测、日志、Trace、缓存、异步任务和容器化。

- [京东软件开发岗（AI 应用方向）](https://zhaopin.jd.com/web/job-info-detail?requementId=220736)
- [海康威视大模型应用软件开发岗位](https://talent.hikvision.com/home/socity/position?postId=B4F6AAF8C5C1FEB7D6C131231EBAB46F)

海康威视的岗位描述比较典型：先用 1～2 周完成原型，然后通过真实数据回放和 A/B 测试持续优化，最后还要负责熔断、限流、降级、安全和监控。

因此，企业真正需要的不是“一个 RAG 页面”，而是：

> 在不确定的模型之上，建立一个可评估、可控制、可维护、能够接入业务的系统。

## 使用 AI 写项目，会不会让项目失去意义

不会。AI 应用工程师本来就应该善用 AI。关键在于自己处在哪一个层次。

- AI 写完后只能运行：这部分暂时还不能算作自己的能力。
- 能解释代码、修改需求、定位错误：已经具备基础工程能力。
- 能设计架构、审查 AI 代码、补充测试、分析失败：这是岗位真正需要的能力。
- 能确定业务指标，并通过实验证明改进有效：这是比较强的 AI 应用工程能力。

可以通过下面的问题检查自己：

- 能否不看代码，画出上传 PDF 到生成回答的完整数据流？
- 为什么选择归一化向量加 `IndexFlatIP`？
- 为什么 Top-3 比 Top-1 好？在哪些问题上可能反而更差？
- 如果 LLM 超时、PDF 解析失败或 Embedding 失败，系统分别处于什么状态？
- 两个用户同时上传 PDF，会发生什么？
- 怎样保证 A 企业无法检索到 B 企业的数据？
- 如何证明加入 reranker 后真的变好了，而不是只展示几个成功案例？

答不出来并不意味着项目没有意义，它只是指出了下一轮需要学习的位置。

## 当前最值得进行的升级

现有的“企业制度 / SOP 知识库”方向是正确的，但不适合同时堆入 Agent、Kubernetes、微调和多模态。更合理的方式是先把当前项目做成一个具备完整闭环的企业知识库。

1. 使用 PostgreSQL + pgvector，实现多文档和索引持久化。
2. 增加知识库、文档、版本、Chunk 和处理状态的数据模型。
3. 使用 Redis + Worker 异步解析文档，支持失败重试和任务状态查询。
4. 增加两个企业、不同部门和 RBAC，验证权限过滤发生在检索阶段。
5. 使用真实的 20～30 份制度或设备手册，构建至少 100 道评测题。
6. 对比向量检索、混合检索和 reranker，报告 Recall@K、引用正确率、拒答率和延迟。
7. 增加 pytest、结构化日志、Trace，以及 Token 和成本统计。
8. 使用 Docker Compose 一键启动，并提供可以重复使用的演示数据。

完成这些升级后，项目描述就不再是：

> 我也做过一个 ChatPDF。

而可以变成：

> 我把一个单文档 RAG Demo 升级为具备持久化、异步处理、租户权限、质量评测和可观测性的企业知识库，并通过实验将某项指标从 X 提升到了 Y。

后者在面试中的分量会高很多。

## 最核心的判断

> 项目的意义，不是证明自己可以不用 AI 写代码；而是证明自己能够利用 AI，交付一个真正理解、能够验证、敢于负责的系统。

以数学硕士和图像处理方向的背景来看，模型理解并不是最大的短板。下一阶段最值得补充的是后端工程、评测和生产化能力。

不要急着再创建很多新项目。把当前这一个项目做到出现真实数据、真实故障和真实指标，就会开始明显接近真正的 AI 应用工程师。
