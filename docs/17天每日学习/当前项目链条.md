# 四、SQLAlchemy 怎么连接 PostgreSQL？

现在问题：

Python代码怎么操作数据库？

难道每次写：

```sql
SELECT *
FROM chunks
WHERE id=1;
```

吗？

可以，但是工程里一般不用。

于是：

SQLAlchemy出现。

它是：

> Python操作数据库的翻译器。

例如：

你的 Model：

```python
class KnowledgeBase(Base):

    __tablename__="knowledge_bases"

    id = Column(Integer, primary_key=True)

    name = Column(String)
```

对应数据库：

```
knowledge_bases表

id
name
```

---

代码：

```python
kb = KnowledgeBase(
    name="公司制度"
)

session.add(kb)

session.commit()
```

SQLAlchemy转换：

变成：

```sql
INSERT INTO knowledge_bases
(name)
VALUES
('公司制度');
```

然后发送给：

```
PostgreSQL
```

所以：

SQLAlchemy解决：

> Python代码如何操作数据库。

# 五、Alembic 在哪里？

这里容易混淆。

很多人认为：

Alembic负责访问数据库。

不是。

它负责：

> 管理数据库结构。

比如：

今天：

你的模型：

```python
class Chunk:

    content

    embedding
```

数据库：

```
chunks

content

embedding
```

明天你增加：

```python
created_at
```

代码变了：

```python
class Chunk:

    created_at
```

但是数据库不知道。

怎么办？

Alembic：

生成：

```
migration文件
```

里面：

```python
def upgrade():

    add_column(
        "chunks",
        "created_at"
    )
```

执行：

```bash
alembic upgrade head
```

数据库变化：

```
chunks

content

embedding

created_at
```

---

所以：

SQLAlchemy:

负责：

```
运行时 CRUD
```

Alembic:

负责：

```
数据库结构升级
```

一个是：

```
数据操作
```

一个是：

```
结构变化
```

# 六、Repository 为什么出现？

假设没有 Repository。

Service里面：

```python

    session.query(Document)

    session.add()

    session.commit()
```

问题：

业务代码和数据库绑死。

以后换数据库：

麻烦。

所以抽出来：

Repository。

结构：

```
Service

   |
   ↓

DocumentRepository

   |
   ↓

SQLAlchemy

   |
   ↓

PostgreSQL
```

例如：

Repository：

```python
class DocumentRepository:


    def create(self, document):

        self.session.add(document)
```

负责：

数据库操作。

---

所以：

Repository解决：

> 数据怎么存取。

# 七、Service 为什么需要？

假设：

上传PDF。

业务：

```
用户上传PDF

↓

解析PDF

↓

切chunk

↓

生成embedding

↓

保存数据库

↓

返回结果
```

如果全部写API：

```python
@app.post("/upload")
def upload():

    parse_pdf()

    split()

    embedding()

    insert_db()
```

API会非常臃肿。

所以：

抽出来：

Service:

```python
class DocumentIngestionService:


    def ingest():

        pdf_service.extract()

        chunk_service.split()

        embedding_service.embed()

        repository.save()
```

Service负责：

> 业务流程。

# 八、API 最上层

API：

FastAPI:

```python

    result = service.ingest()
```

- 接收请求
    
- 参数校验
    
- 返回响应
    

不要负责：

- SQL
    
- PDF解析

# 十二、对于 AI 应用开发面试，你应该能讲出的项目链路

以后面试问：

> 介绍一下你的 RAG 系统后端架构。

你可以说：

> 我使用 Docker Compose 部署 PostgreSQL + pgvector 作为向量数据库，通过 SQLAlchemy ORM 管理数据库访问，使用 Alembic 管理数据库 schema 迁移。在代码结构上采用 API、Service、Repository 分层，API负责请求处理，Service负责文档解析、切片、Embedding生成等业务流程，Repository封装数据库CRUD操作，最终将文档chunk和向量存储到PostgreSQL中，并通过pgvector完成相似度检索。

这个就是一个标准 AI 应用开发工程师的回答。

你现在其实已经写到了这个架构，只是之前没有把这些模块串起来。你接下来学习任何新代码，都应该强制自己问一句：

> **这个代码属于这条链里的哪一层？它为什么应该放这里？**

这样你的项目理解会快很多。
