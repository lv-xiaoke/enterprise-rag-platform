# Day 28：Transformer 与 LLM 面试回答

## 1. Attention 是什么？

Attention 是一种让每个 Token 根据当前任务，从其他 Token 中选择并汇总信息的机制。它先计算当前位置与各位置的相关性分数，再用 softmax 把分数变成权重，最后对对应的信息做加权求和。与固定平均不同，Attention 的权重会随输入内容和当前位置动态变化。比如理解“苹果发布了新手机”时，“苹果”可以更多关注“发布”和“手机”，从而判断这里指公司而不是水果。Attention 权重较高只表示模型在当前层和当前注意力头中更关注该位置，不一定等于人类可直接解释的因果关系。

## 2. Q、K、V 分别有什么作用？

Q、K、V 是输入 Token 经过三组可训练矩阵投影后得到的不同表示。Q 可以理解为当前位置“想找什么”，K 表示每个位置“能用什么特征被匹配”，V 则是匹配成功后真正传递的信息。模型用 Q 和所有 K 计算相似度，经过缩放和 softmax 得到权重，再用权重对 V 加权求和。例如“我爱苹果”中，“我”的 Q 会分别与三个词的 K 匹配，然后按权重读取它们的 V。Q、K、V 的含义不是人工固定写入的，而是模型在训练过程中学出来的。

## 3. 为什么需要 Multi-head Attention？

Multi-head Attention 会使用多组 Q、K、V 投影并行计算注意力，再把各个头的结果拼接并投影。这样模型可以在不同表示子空间中同时观察多种关系，例如局部搭配、远距离指代和语义关联。相比只有一个注意力头，多头机制通常具有更强的表达能力。各个头的作用是训练形成的，不保证某个头永远只负责语法、另一个头永远只负责指代。增加注意力头也会带来额外计算，因此头数不是越多越好，还要与模型维度和计算预算配合。

## 4. 为什么 Transformer 需要位置编码？

纯 Self-Attention 主要根据 Token 内容计算关系，本身不能充分区分 Token 的先后顺序。位置编码会把绝对或相对位置信息加入 Token 表示，让模型知道“谁在前、谁在后”以及相隔多远。例如“我批评了他”和“他批评了我”包含相似词语，但顺序改变后含义完全不同。位置编码解决顺序信息，因果掩码则限制生成模型不能看到未来 Token，二者不是同一个概念。位置方法还会影响模型处理长文本的能力，超过训练时常见长度后效果不一定保持稳定。

## 5. Residual 和 LayerNorm 分别解决什么问题？

Residual Connection 把子层输出与原输入相加，常写成 `x + F(x)`，可以保留原信息并让梯度更容易通过深层网络传播。LayerNorm 会对单个 Token 的特征维度做归一化，再使用可学习参数调整数值，有助于稳定训练。简单来说，Residual 更关注信息和梯度通路，LayerNorm 更关注每层数值尺度。它们经常一起使用，但作用不同，不能互相替代。不同 Transformer 可能采用 Pre-Norm 或 Post-Norm，因此 LayerNorm 的具体位置并不总是完全相同。

## 6. BERT 和 GPT 有什么区别？

经典 BERT 主要使用 Transformer Encoder，通过双向上下文理解文本，并使用遮盖词预测进行预训练。GPT 主要使用带因果掩码的 Transformer Decoder，根据前面的 Token 逐个预测下一个 Token，因此更适合连续生成。可以简单概括为：BERT 更偏向文本理解和编码，GPT 更偏向自回归生成。当前 Mini RAG 项目的 BGE Embedding 模型负责把问题和文档编码为检索向量，而 LLM API 负责根据 Prompt 生成回答，两者承担的任务不同。这个区分不是绝对限制，现代 GPT 也能完成分类和抽取等理解任务，BERT 类模型经过改造后也可以用于更多任务。

## 7. LLM 的训练和推理有什么区别？

训练阶段会进行前向计算、计算损失、反向传播并更新模型参数，通常需要大量数据、算力和显存。推理阶段固定模型参数，只根据输入计算并输出结果，不进行反向传播。生成式 LLM 的推理通常先用 Prefill 处理完整 Prompt，再通过 Decode 逐个生成新 Token。当前 Mini RAG 项目调用的是已经训练完成的 LLM API，所以属于推理，不是训练。上传 PDF、生成 Embedding 和建立 FAISS 索引只是在准备外部检索数据，并没有修改 LLM 参数，因此也不是微调。

## 8. KV Cache 是什么，为什么能加速生成？

KV Cache 会保存 Transformer 各层中历史 Token 已经计算好的 Key 和 Value。生成下一个 Token 时，模型只需计算新 Token 的 Q、K、V，再让新的 Q 查询缓存中的历史 K 和 V，不必重复计算整个历史序列。它减少了自回归生成中的重复计算，所以能明显提高逐 Token 生成速度。代价是缓存会占用额外显存，并随上下文长度、模型层数和并发请求数增加。KV Cache 是模型推理时的内部缓存，与当前项目保存文档向量的 FAISS 索引不是一回事。

## 9. Temperature 如何影响生成？

Temperature 会在 softmax 前缩放模型输出的 logits，常写成 `softmax(logits / T)`。较低的 Temperature 会让概率分布更集中，模型更倾向选择高概率 Token；较高的值会让分布更平坦，输出通常更多样，但出错风险也可能增加。当前 `llm_service.py` 没有显式传入 `temperature`，因此使用的是服务端或模型的默认设置。RAG 问答更重视依据资料准确作答，通常不需要很高的随机性。Temperature 改变的是采样分布，不会增加模型已经学到的知识，而且设为 0 也不一定保证所有环境下逐字完全相同。

## 10. LoRA 是什么？

LoRA 是一种参数高效微调方法，它冻结大部分原模型参数，只训练添加在部分权重旁边的低秩矩阵。这样可以用更少的可训练参数和显存，让模型适应特定任务、格式或表达风格。训练完成后只需保存较小的 LoRA 适配器，不必为每个任务保存一份完整模型。当前 Mini RAG 项目没有使用 LoRA，而是通过检索外部 PDF 内容给模型补充上下文。需要频繁更新且要求来源可追溯的知识通常更适合 RAG，LoRA 也不能简单当作外部知识库使用。

## 11. 量化是什么，它和 LoRA 有什么区别？

量化是用更低精度表示模型权重或计算，例如从 FP16 降到 INT8 或 4-bit，以减少模型体积、显存占用和部分硬件上的推理成本。LoRA 主要解决“怎样用较少可训练参数适配模型”，量化主要解决“怎样用更低精度部署模型”，二者目标不同。量化通常不负责教给模型新的任务行为，而 LoRA 会通过训练改变模型的部分有效参数。两者可以组合，例如先量化基础模型，再训练或加载 LoRA 适配器。量化可能带来精度损失，实际加速效果也依赖硬件、推理框架和算子支持，并不是位数越低就一定越好。
