你可以先把一次 HTTP 请求想成：**你给服务器寄一个快递包裹**。

其中最容易混淆的就是 **请求头（Header）** 和 **请求体（Body）**。

### 1. 请求头是什么？

请求头可以理解成**快递单上的信息**。

比如快递单上会写：

```text
寄件人：
收件人：
快递类型：
包裹类型：
```

HTTP 请求头里类似：

```http
Content-Type: application/json
Authorization: Bearer xxx
User-Agent: Chrome
X-Client-Name: day3-test
```

它们通常不是你真正要传输的“业务内容”，而是**描述这次请求的信息**。

例如：

```http
Authorization: Bearer abc123
```

意思是：

> 我是谁 / 我的身份凭证是什么。

而：

```http
Content-Type: application/json
```

是在告诉服务器：

> 我这次发送的数据是 JSON。

你代码里的：

```http
X-Client-Name: day3-test
```

则是在告诉服务器：

> 这次请求来自一个叫 `day3-test` 的客户端。

---

### 2. 请求体是什么？

请求体 `Body` 可以理解成**快递箱子里面真正装的东西**。

比如你做一个聊天接口：

```http
POST /chat
```

发送：

```json
{
    "message": "你好，请介绍一下 FastAPI"
}
```

这里：

```json
{
    "message": "你好，请介绍一下 FastAPI"
}
```

就是**请求体**。

所以可以记成：

```text
请求头 Header
    ↓
描述请求的信息

请求体 Body
    ↓
真正要交给服务器处理的数据
```

例如一个完整请求大概长这样：

```http
POST /chat HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: application/json
Authorization: Bearer abc123
X-Client-Name: day3-test

{
    "message": "你好"
}
```

上面可以分成两块：

```text
Content-Type: application/json
Authorization: Bearer abc123
X-Client-Name: day3-test

↑ 请求头 Header
```

然后：

```json
{
    "message": "你好"
}
```

这是：

```text
↑ 请求体 Body
```

## 3. 再来看你的 FastAPI 代码

你的代码：

```python
@app.get("/request-info")
async def request_info(
    x_client_name: str | None = Header(default=None),
) -> dict[str, str]:
```

先只看这一行：

```python
x_client_name: str | None = Header(default=None)
```

可以拆成三部分：

```python
x_client_name
```

这是 Python 变量名。

```python
str | None
```

表示：

> 它可能是字符串，也可能是 `None`。

然后：

```python
Header(default=None)
```

这是最关键的。

它告诉 FastAPI：

> **不要去 URL、请求体里找 `x_client_name`，去 HTTP 请求头里面找。**

所以：

```python
x_client_name: str | None = Header(default=None)
```

你可以暂时脑补成：

```python
x_client_name = 从请求头里读取 X-Client-Name
```

---

## 4. 为什么代码是 `x_client_name`，HTTP 却是 `X-Client-Name`？

这是 FastAPI 帮你自动转换的。

Python 变量名习惯写：

```python
x_client_name
```

因为 Python 变量不能写：

```python
x-client-name
```

这会被 Python 理解成：

```python
x - client - name
```

也就是减法。

但是 HTTP 请求头通常使用：

```http
X-Client-Name
```

所以 FastAPI 自动帮你：

```text
Python

x_client_name
    ↓ FastAPI 转换

HTTP Header

X-Client-Name
```

大小写这里不用太纠结，HTTP Header 名称通常是**大小写不敏感的**。

---

## 5. 实际调用的时候发生了什么？

假设你访问：

```text
GET /request-info
```

同时发送请求头：

```http
X-Client-Name: day3-test
```

FastAPI 收到 HTTP 请求之后，就会做：

```text
收到 HTTP 请求
        ↓
找到请求头

X-Client-Name: day3-test
        ↓
因为代码写了

Header(default=None)
        ↓
FastAPI 读取它
        ↓
赋值给 Python 参数

x_client_name = "day3-test"
```

所以函数真正执行的时候，可以近似理解成：

```python
async def request_info(
    x_client_name="day3-test"
):
```

---

## 6. 那 `default=None` 又是什么意思？

意思是：

> 如果客户端没有发送 `X-Client-Name`，也不要报错，默认设置为 `None`。

例如客户端什么都没传：

```http
GET /request-info
```

那么：

```python
x_client_name = None
```

如果传了：

```http
X-Client-Name: day3-test
```

那么：

```python
x_client_name = "day3-test"
```

所以：

```python
str | None
```

也就很好理解了：

```text
传了 Header
↓
str

没传 Header
↓
None
```

## 7. Header 和 Body 到底什么时候用？

你以后做 AI 后端时，可以这样区分。

比如 `/chat`：

```http
POST /chat
```

真正聊天内容：

```json
{
    "message": "什么是 RAG？"
}
```

应该放 **Body**。

而类似：

```http
Authorization: Bearer sk-xxx
X-Client-Name: web
Content-Type: application/json
```

这些放 **Header**。

可以简单记一句：

> **Body 放“我要你处理什么”，Header 放“这次请求是什么情况”。**

比如：

```text
POST /chat

Header:
Authorization: Bearer abc123
Content-Type: application/json
X-Client-Name: my-app

Body:
{
    "message": "你好"
}
```

服务器理解成：

```text
谁发的？
→ Authorization

从哪个客户端来的？
→ X-Client-Name

发的是什么格式？
→ Content-Type

真正让我处理什么？
→ Body 里的 message
```

---

你现在这个接口最核心的执行过程就是：

```text
客户端
   │
   │ GET /request-info
   │
   │ Header:
   │ X-Client-Name: day3-test
   ↓
FastAPI
   │
   │ Header(default=None)
   │
   │ 去请求头寻找 X-Client-Name
   ↓
x_client_name = "day3-test"
   │
   ↓
request_info() 函数继续执行
```

如果你把这个过程理解了，接下来学习 FastAPI 的 **Path、Query、Header、Body** 就会非常顺，因为本质上它们只是在回答一个问题：

**“客户端传过来的这个参数，到底放在 HTTP 请求的哪个位置？”**
