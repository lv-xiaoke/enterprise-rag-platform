# Mini RAG 项目终端命令速查（Windows PowerShell）

这份速查表整理自本项目的 `Day1.md` ～ `Day30.md`、`README.md` 和当前代码结构。它不是一份追求“大而全”的命令百科，而是优先收录这个 Mini RAG 后端中最常用、最值得真正记住的命令。

> 默认环境：Windows PowerShell；默认工作目录：项目根目录。命令中的路径、文件名和提交说明需要按实际情况替换。

## 2. 先看懂 PowerShell 命令的几个规则

### 2.1 提示符不是命令的一部分

终端可能显示：

```text
(.venv) PS D:\...\260804_mini-rag-backend>
```

这里只需要输入 `>` 后面的命令，不要把 `(.venv) PS ...>` 一起复制。

### 2.2 相对路径从当前目录开始计算

例如：

```powershell
Get-Content .\app\main.py
```

这里的 `.` 表示当前目录。因此，大部分项目命令都应该先在项目根目录执行。用下面两条命令确认当前位置：

```powershell
Get-Location
Get-ChildItem
```

### 2.3 PowerShell 用反引号续行

```powershell
Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/health" `
    -Method Get
```

反引号 `` ` `` 表示下一行仍属于同一条命令。它必须是该行最后一个字符，后面不要留空格。

### 2.4 管道把前一条命令的结果交给后一条

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/history" |
    Select-Object -Last 2 |
    ConvertTo-Json -Depth 3
```

这里依次表示：请求历史记录 → 只取最后两条 → 格式化成 JSON。

### 2.5 常用快捷键

| 操作 | 快捷键 |
| --- | --- |
| 停止当前程序或服务 | `Ctrl+C` |
| 补全路径或命令 | `Tab` |
| 找回上一条命令 | `↑` |
| 清屏 | `Ctrl+L` 或执行 `Clear-Host` |

### 2.6 忘记参数时现场查帮助

```powershell
# 查看 PowerShell 命令示例
Get-Help Get-ChildItem -Examples

# 查看某个命令实际来自哪里
Get-Command python

# 查看别名对应的完整命令，例如 cd 对应 Set-Location
Get-Alias cd

# 常见程序自己的帮助
python --help
python -m pip --help
git status -h
docker run --help
```

不必一次背下所有参数。先记住命令负责什么，再用 `-h`、`--help` 或 `Get-Help` 查具体写法。

## 3. 目录和文件操作

### 3.1 查看和切换目录

```powershell
# 显示当前目录
Get-Location

# 列出当前目录内容
Get-ChildItem

# 连隐藏文件一起显示，例如 .env、.gitignore
Get-ChildItem -Force

# 进入目录；路径有空格时一定加引号
cd "D:\某个目录\项目名"

# 返回上一级
cd ..

# 回到刚才所在的位置
cd -
```

`cd` 是 `Set-Location` 的常用别名。

### 3.2 查看文件

```powershell
# 显示整个文本文件
Get-Content .\README.md

# 显示文件基本信息
Get-Item .\requirements.txt

# 在文件中查找文字
Select-String -Path .\app\main.py -Pattern "rag"

# 检查路径是否存在
Test-Path .\data\documents\sample.pdf
```

不要在录屏、截图或共享终端中执行 `Get-Content .env`，否则 API Key 可能被展示出来。

### 3.3 创建目录和文件

```powershell
# -Force 表示目录已存在时也不报错
New-Item -ItemType Directory -Force .\data\documents

# 创建空文件
New-Item -ItemType File .\docs\新笔记.md

# 复制一个文件
Copy-Item .\原文件.pdf .\data\documents\sample.pdf

# 用 VS Code 打开当前项目或指定文件
code .
code .\app\main.py
```

### 3.4 删除前先确认目标

删除无法靠猜测恢复。只删除已经确认的单个文件，不使用递归批量删除：

```powershell
Get-Item -LiteralPath ".\明确的文件名.tmp"
Remove-Item -LiteralPath ".\明确的文件名.tmp"
```

不要把项目根目录、通配符或不确定的变量作为删除目标。

## 4. Python 与虚拟环境

### 4.1 检查 Python

```powershell
python --version
where.exe python
python -c "import sys; print(sys.executable)"
```

三个命令分别查看：Python 版本、系统能找到哪些 Python、当前实际使用哪个解释器。激活成功后，最后一条通常应该指向本项目的 `.venv`。

### 4.2 创建和激活虚拟环境

通常只有第一次配置项目时才创建：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

如果 PowerShell 阻止激活脚本，可只对当前终端临时放开：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

`-Scope Process` 只影响当前 PowerShell 窗口，关闭窗口后失效。

### 4.3 管理依赖

```powershell
# 安装项目锁定的全部依赖
python -m pip install -r requirements.txt

# 安装一个依赖
python -m pip install pypdf

# 查看是否安装、版本和安装位置
python -m pip show pypdf

# 列出当前环境全部依赖
python -m pip list

# 更新 pip
python -m pip install --upgrade pip
```

优先写 `python -m pip`，因为它能明确使用当前 `python` 对应的 pip，减少多个 Python 环境混用的问题。

笔记中还多次使用：

```powershell
python -m pip freeze > requirements.txt
```

这会用当前环境的完整依赖列表**覆盖** `requirements.txt`。执行前先确认虚拟环境正确，并在执行后检查差异：

```powershell
git diff -- requirements.txt
```

### 4.4 不激活环境也能指定项目 Python

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

这种写法更长，但能非常明确地使用本项目的虚拟环境。

### 4.5 快速执行一小段 Python

```powershell
python -c "from app.main import app; print(app.title)"
python -c "import faiss; print(faiss.__version__)"
```

适合做快速导入检查，不必专门创建临时 `.py` 文件。

## 6. 测试 HTTP 接口

### 6.1 GET：健康检查和历史记录

```powershell
Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/health" `
    -Method Get

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/history" `
    -Method Get
```

简单 GET 请求也可简写为：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/health"
```

### 6.2 POST：普通聊天

```powershell
$body = @{
    message = "请用一句话解释什么是 RAG"
} | ConvertTo-Json

$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($body)

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/chat" `
    -Method Post `
    -ContentType "application/json; charset=utf-8" `
    -Body $bodyBytes
```

把 JSON 转为 UTF-8 字节，可以减少 Windows PowerShell 发送中文时的编码问题。

### 6.3 POST：上传 PDF

```powershell
curl.exe `
    -X POST `
    -F "file=@data/documents/sample.pdf;type=application/pdf" `
    "http://127.0.0.1:8000/upload"
```

这里明确写 `curl.exe`，避免 Windows PowerShell 旧版本中 `curl` 别名和真正的 curl 程序混淆。

### 6.4 POST：RAG 提问

必须先成功上传 PDF，再提问：

```powershell
$body = @{
    question = "什么是 RAG，基础流程包括哪些步骤？"
} | ConvertTo-Json

$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($body)

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/rag/chat" `
    -Method Post `
    -ContentType "application/json; charset=utf-8" `
    -Body $bodyBytes
```

服务重启后，内存中的 FAISS 索引会消失，需要重新执行上传命令。

### 6.5 发送自定义请求头

```powershell
Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/request-info" `
    -Method Get `
    -Headers @{
        "X-Client-Name" = "powershell-client"
    }
```

### 6.6 查看失败响应

```powershell
try {
    Invoke-RestMethod `
        -Uri "http://127.0.0.1:8000/chat" `
        -Method Post `
        -ContentType "application/json" `
        -Body "{}"
} catch {
    $_.Exception.Response.StatusCode.value__
    $_.ErrorDetails.Message
}
```

这比只看到一行报错更容易判断是 4xx 请求问题还是 5xx 服务问题。

## 8. Git：最需要形成习惯的完整流程

### 8.1 先检查，不要上来就 `git add .`

```powershell
# 简洁显示修改、新文件和删除
git status --short

# 查看尚未暂存的具体修改
git diff

# 只查看指定文件
git diff -- app\main.py app\services\rag_service.py

# 查看变化量，不展开全部内容
git diff --stat

# 检查尾随空格等常见格式问题；无输出通常表示通过
git diff --check
```

常见的 `git status --short` 标记：

| 标记 | 含义 |
| --- | --- |
| `??` | Git 尚未跟踪的新文件 |
| ` M` | 已修改、尚未暂存 |
| `M ` | 已暂存 |
| `A ` | 新文件已暂存 |

新文件是未跟踪状态时，普通 `git diff` 不会显示其内容，所以要同时看 `git status --short` 并直接检查文件。

### 8.2 确认敏感文件和本地数据被忽略

```powershell
git check-ignore -v .env
git check-ignore -v .\data\chat.db
git check-ignore -v .\data\documents\sample.pdf
```

输出会告诉你是哪一条 `.gitignore` 规则生效。若 `.env` 或本地 PDF 没被忽略，先解决，不要继续暂存。

### 8.3 明确选择文件并暂存

```powershell
git add app\main.py app\services\rag_service.py docs\终端命令速查.md
```

推荐明确列出文件，比 `git add .` 更容易避免把 `.env`、数据库、测试 PDF 或无关修改带进去。

检查已经暂存的内容：

```powershell
git status
git diff --cached
git diff --cached --stat
```

### 8.4 提交并检查结果

```powershell
git commit -m "docs: add terminal command cheatsheet"
git log -1 --oneline
git status --short
```

常见提交前缀：

| 前缀 | 适用场景 |
| --- | --- |
| `feat:` | 新功能 |
| `fix:` | 修复问题 |
| `refactor:` | 重构但不改变功能 |
| `test:` | 测试和评估 |
| `docs:` | 文档修改 |
| `build:` | 构建或 Docker |
| `chore:` | 初始化、配置等杂项 |

### 8.5 远程仓库常用命令

```powershell
# 查看远程仓库
git remote -v

# 获取远程信息但不自动合并
git fetch origin

# 当前项目主分支是 master；只允许快进合并
git pull --ff-only origin master

# 推送本地 master
git push origin master
```

拉取或推送前先执行 `git status --short`。有未提交修改或不清楚冲突如何处理时，先暂停并检查，不要盲目覆盖文件。

### 8.6 第一次获取或初始化项目

克隆已有仓库：

```powershell
git clone https://github.com/lv-xiaoke/260804_mini-rag-backend.git
cd .\260804_mini-rag-backend
```


## 9. Docker

### 9.1 检查 Docker 是否可用

```powershell
docker --version
docker info
```

`docker --version` 只证明客户端命令存在；`docker info` 还能检查 Docker Engine 是否正在运行。

### 9.2 构建镜像

在项目根目录执行：

```powershell
docker build -t mini-rag-backend .
```

可以拆开理解：

| 部分 | 含义 |
| --- | --- |
| `docker build` | 根据 Dockerfile 构建镜像 |
| `-t mini-rag-backend` | 给镜像命名 |
| `.` | 使用当前目录作为构建上下文 |

查看镜像：

```powershell
docker image ls mini-rag-backend
```

### 9.3 运行容器

```powershell
docker run `
    --name mini-rag-backend-local `
    --rm `
    -p 127.0.0.1:8000:8000 `
    --env-file .env `
    mini-rag-backend
```

关键参数：

| 参数 | 含义 |
| --- | --- |
| `--name` | 设置便于识别的容器名 |
| `--rm` | 容器停止后自动删除容器本身 |
| `-p 主机端口:容器端口` | 把本机 8000 映射到容器 8000 |
| `--env-file .env` | 运行时注入环境变量，不写入镜像 |

前台运行时按 `Ctrl+C` 停止。因为使用了 `--rm`，停止后容器会自动删除；容器内的 SQLite、模型缓存和内存索引不会保留。

### 9.4 查看容器状态和日志

```powershell
# 正在运行的容器
docker ps

# 包括已经停止的容器
docker ps -a

# 查看指定容器日志
docker logs mini-rag-backend-local

# 停止指定容器
docker stop mini-rag-backend-local
```

如果容器已经因 `--rm` 被自动删除，`docker ps -a` 中不会再看到它。

## 10. 常见报错如何排查

### 10.1 `python` 不是命令

```powershell
where.exe python
python --version
```

若找不到，通常是 Python 未安装或没有加入 PATH。

### 10.2 激活虚拟环境时报“禁止运行脚本”

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### 10.3 `No module named ...`

依次检查：

```powershell
Get-Location
python -c "import sys; print(sys.executable)"
python -m pip show 包名
```

最常见原因是：不在项目根目录、没有激活 `.venv`、依赖装到了另一个 Python。

### 10.4 `No module named 'app'`

回到项目根目录再启动：

```powershell
cd "D:\my_develop\A_work_program\AI-study-2608\260804_mini-rag-backend"
python -m uvicorn app.main:app --reload
```

### 10.5 8000 端口被占用

先看哪个进程占用端口：

```powershell
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue
```

优先回到原来的 Uvicorn 或 Docker 终端按 `Ctrl+C`。也可以临时换端口：

```powershell
python -m uvicorn app.main:app --reload --port 8001
```

相应地把测试地址改为 `http://127.0.0.1:8001`。

### 10.6 接口连接失败

按顺序检查：

```powershell
# 服务终端是否仍在运行
Get-NetTCPConnection -LocalPort 8000 -ErrorAction SilentlyContinue

# 最简单的接口能否访问
Invoke-RestMethod "http://127.0.0.1:8000/health"
```

如果 `/health` 正常但 `/rag/chat` 失败，确认是否在本次服务启动后重新上传过 PDF，以及 `.env` 中的 LLM 配置是否齐全。

### 10.7 中文输出乱码

```powershell
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
$OutputEncoding = [System.Text.UTF8Encoding]::new()
$env:PYTHONIOENCODING = "utf-8"
```

发送中文 JSON 时仍应使用 UTF-8 字节：

```powershell
$bodyBytes = [System.Text.Encoding]::UTF8.GetBytes($body)
```

### 10.8 Docker 客户端存在但无法连接

```powershell
docker --version
docker info
```

如果第一条成功、第二条失败，通常是 Docker Desktop 或 Docker Engine 尚未启动。
