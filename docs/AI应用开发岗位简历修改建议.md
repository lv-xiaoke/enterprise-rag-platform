# AI 应用开发岗位简历修改建议

## 一、总体结论

当前背景适合投递 **AI 应用开发工程师、RAG 工程师、Agent 应用开发工程师**等岗位。

主要优势是：

- 数学、机器学习和算法基础较好；
- 具有 RAG、Agent 项目实践；
- 能够独立完成从后端逻辑到交互界面的开发；
- 有科研、建模竞赛和实验评测经验。

当前简历的主要问题不是经历不足，而是部分项目描述快于实际开发进度，同时缺少可验证的指标。后续修改应围绕三个目标展开：

1. 突出 AI 应用工程岗位需要的后端、RAG、Agent 和工程化能力；
2. 使用真实数据证明项目效果；
3. 确保简历、代码仓库、README 和面试表述完全一致。

近期 AI 应用岗位通常重视以下能力：

- Python、FastAPI 和 RESTful API；
- RAG、Agent、Prompt Engineering、Function Calling/MCP；
- PostgreSQL、向量数据库和缓存；
- Docker、测试、部署和问题排查；
- 检索质量、任务成功率、延迟、成本和稳定性评测；
- 更高阶岗位还会关注 LangGraph、CI/CD、可观测性、安全校验、限流和降级。

参考岗位：

- [百度校园招聘——大模型研发工程师](https://talent.baidu.com/jobs/detail/GRADUATE/3b3888c3-5d8b-4c62-9bbb-a142c24e7d86)
- [海康威视招聘——大模型应用软件开发](https://talent.hikvision.com/home/socity/position?postId=B4F6AAF8C5C1FEB7D6C131231EBAB46F)

## 二、简历应该包含哪些内容

建议将简历控制为一页，并按照以下顺序组织。

### 1. 个人信息与求职意向

建议包含：

- 姓名；
- 手机号和邮箱；
- GitHub 或个人主页；
- 求职意向：`AI 应用开发工程师｜RAG / Agent 方向`；
- 预计毕业时间；
- 可实习时间、每周可到岗天数以及可连续实习月数。

不建议添加泛泛的自我评价、籍贯、婚姻状态、兴趣爱好等与岗位关系较弱的信息。

### 2. 教育背景

保留硕士、本科、GPA、研究方向和核心荣誉。

建议写法：

> 2025.09–2028.06（预计）｜电子科技大学｜数学｜硕士  
> GPA：3.96/4.0；研究方向：深度学习与图像处理

本科部分建议将“信息与计算科学（双一流专业）”改为：

> 湘潭大学（双一流）｜信息与计算科学

如果该专业确实入选国家级一流本科专业，可以使用对应的官方称谓。

“师从国家青年长江学者”对 AI 应用开发岗位的帮助有限，可以删除，为项目成果和指标腾出空间。

### 3. 专业技能

专业技能应按照 AI 应用系统的技术链路分类，而不是简单罗列模型名称。

推荐结构：

- **编程与后端**：Python、FastAPI、RESTful API、Pydantic、HTTPX、异步编程、pytest
- **大模型应用**：RAG、文档解析与切分、Embedding、向量检索、Prompt Engineering、ReAct Agent、Function Calling/MCP
- **数据与工程**：PostgreSQL、pgvector、Chroma/FAISS、SQLAlchemy、Alembic、Docker Compose、Git、Linux
- **机器学习**：PyTorch、Transformers、BGE Embedding、NumPy、Pandas、CatBoost

只写能够解释原理、展示代码或回答面试追问的技术。尚未实际使用的 LangGraph、Redis、Kubernetes、CI/CD 等技术，不应仅为了通过关键词筛选而提前写入。

### 4. 核心 AI 项目

保留两个核心项目即可，并形成清晰分工：

- **企业知识库 RAG 后端**：突出数据模型、持久化、知识库隔离、检索评测、事务、测试和部署；
- **企业办公 Agent 系统**：突出意图路由、ReAct/工具调用、结构化与非结构化数据协同、异常兜底和交互界面。

每个项目建议包含：

1. 项目名称、时间和个人角色；
2. 技术栈；
3. GitHub、在线演示或演示视频；
4. 三条项目描述，分别说明核心实现、关键设计和量化结果。

### 5. 学术科研

FLRR 科研项目可以保留，但建议压缩为两条：

- 第一条说明研究问题、方法和个人负责内容；
- 第二条给出 ACC、NMI、PUR、运行时间或内存占用等具体实验结果。

“达到 SOTA”“显著降低计算量”等表述需要给出具体数据和对比对象。“即将投稿”的证明力较弱，正式投稿后再写“论文在投”。

### 6. 奖项

数学建模竞赛不必继续作为两个完整项目展开，可以合并成一至两行：

> **竞赛荣誉**：MCM/ICM Honorable Mention（H 奖）、全国大学生数学建模竞赛省一等奖（队长）；具备 CatBoost、遗传算法、NSGA-II 等建模实践。

MCM/ICM H 奖建议使用官方名称 `Honorable Mention`，不建议写成“国际级二等奖”。

## 三、当前简历最需要修改的地方

### 1. 解决项目描述与仓库现状不一致的问题

当前简历已经将以下能力写成完成状态：

- PostgreSQL/pgvector 向量检索；
- 多知识库、多文档管理；
- 数据库事务与失败回滚；
- 服务重启后的数据恢复；
- Recall@K、MRR、拒答正确率和延迟评测；
- pytest 关键链路测试。

但当前代码仓库仍以 FAISS 版本为主，README 说明仅维护最近一次上传的 PDF，服务重启后需要重新上传；这些升级项也仍然列在 17 天开发计划中。

因此，在对应功能尚未完成并通过验收前，应当：

- 将项目日期改为 `2026.08–至今`，不能提前写成 2026.09 已完成；
- 未完成的能力不要使用“实现、验证、覆盖”等完成时表述；
- 可以将项目标记为“在研”，区分已经实现的能力和正在升级的能力；
- 所有功能真正完成后，再写入最终简历并补充真实指标。

这是当前简历优先级最高的问题。AI 项目通常会被面试官检查 GitHub，或者围绕数据表、事务边界、检索 SQL、测试方法和评测计算方式连续追问。

### 2. 避免技能描述过于宽泛

当前的“Transformer、CNN、RNN/LSTM；RAG、Agent、MCP 等”更像课程知识清单，不能直接证明应用开发能力。

“AI 赋能”“制作 Skill 仓库赋能论文写作”等表达也较宽泛。如果保留，应说明具体实现，例如：

- Skill 仓库包含多少个可复用工作流；
- 解决了论文检索、实验分析、LaTeX 修改还是文献管理问题；
- 是否有 GitHub 地址、使用次数或实际效率提升。

否则建议暂时删除。

### 3. 避免两个项目内容重复

两个 AI 项目都在强调 RAG、切分、向量存储和 Top-K，会让招聘者认为第二个项目只是更换框架后的重复实现。

应当明确区分：

- RAG 后端项目回答“如何把企业知识库做得可管理、可评测、可恢复”；
- Agent 项目回答“如何让模型正确选择工具、调用业务数据并完成多步骤任务”。

### 4. 用数字替换宣传性形容词

建议删除或减少以下表达：

- 精准预测；
- 高鲁棒性；
- 显著提升；
- 科学筛选；
- 高效求解；
- 核心大脑；
- 有效降低幻觉；
- 完成全栈落地。

优先写入以下可验证数据：

- 评测集问题数量与问题类型；
- Recall@1/3/5、MRR、拒答正确率；
- P50/P95 检索延迟；
- 文档数、总页数和 Chunk 数；
- 文档入库耗时；
- pytest 用例数以及覆盖的关键场景；
- Agent 工具数量和任务成功率；
- API 异常处理类型；
- Docker 是否能一条命令复现；
- 单次任务 Token 成本或调用次数。

例如，当前已经完成的 FAISS 基线可以真实写成：

> 建立含 10 道可回答题和 2 道无依据问题的固定评测集；在 `chunk_size=200、overlap=40` 条件下，Recall@1 为 90%、Recall@3 为 100%，12 道最终回答均通过人工核验。

这比“优化 Top-K，有效降低模型幻觉”更有说服力。

### 5. 压缩非核心经历

对于 AI 应用岗位，数学建模比赛和科研经历能够证明算法基础，但不应压过 RAG 和 Agent 项目。

建议：

- 两个 AI 项目占简历主要篇幅；
- FLRR 科研保留两条；
- 数学建模经历合并成奖项和一行技术摘要；
- 整份简历控制在一页。

## 四、当前阶段可安全使用的 RAG 项目表述

在 pgvector、多知识库、事务和自动化测试尚未全部完成时，可以暂时使用以下版本：

### 2026.08–至今｜可评测企业知识库 RAG 后端｜独立开发

**技术栈**：Python、FastAPI、BGE、FAISS、DeepSeek API、Docker

- 基于 FastAPI 实现 PDF 上传、按页解析、重叠切分、BGE 中文向量化、Top-K 检索及带页码和原文引用的大模型问答链路。
- 建立 12 道固定评测集，包含事实、综合及无依据问题；基线实验 Recall@1 为 90%、Recall@3 为 100%，并通过对比实验确定 Top-3 配置。
- 正在将内存 FAISS 架构升级为 PostgreSQL/pgvector 持久化方案，增加多知识库隔离、文档状态管理、失败回滚及自动化测试。

等升级全部完成并验收后，删除“正在”，补充以下实际数据：

- Recall@1/3/5；
- MRR；
- 拒答正确率；
- P50/P95 检索延迟；
- 测试用例数；
- 文档数、页数和 Chunk 数；
- 重启恢复测试结果。

## 五、完成 pgvector 版本后的项目模板

以下模板只能在功能真实完成后使用，方括号中的数据必须替换为实际测量值。

### 2026.08–2026.09｜企业制度与 SOP 智能知识库 RAG 后端｜独立开发

**技术栈**：Python、FastAPI、PostgreSQL、pgvector、SQLAlchemy、Alembic、BGE、pytest、Docker Compose

- 基于 FastAPI、BGE 和 PostgreSQL/pgvector 实现 PDF 解析、文本切分、向量入库、知识库范围检索及大模型问答，支持多知识库、多文档管理，并返回文档名称、页码和原文等可追溯来源。
- 设计 KnowledgeBase、Document 和 Chunk 数据模型，通过文档处理状态、数据库事务和失败回滚避免不完整数据进入检索；完成服务重启恢复以及至少 `[N]` 份文档的持久化验收。
- 建立包含 `[N]` 道问题的企业制度评测集，取得 Recall@1/3/5=`[数值]`、MRR=`[数值]`、拒答正确率=`[数值]`，P95 检索延迟为 `[数值] ms`；编写 `[N]` 个 pytest 用例覆盖知识库隔离、状态过滤、来源映射和异常输入。

## 六、Agent 项目的修改方向

当前 Agent 项目应减少与 RAG 后端重复的内容，重点体现工具调用和业务任务执行。

建议改写思路：

### 2026.04–2026.07｜基于大模型的企业智能办公 Agent 系统｜独立开发

**技术栈**：Python、LangChain、ReAct、Chroma、Streamlit、YAML

- 基于 ReAct 架构注册规章问答、员工数据查询和周报生成等 3 类工具，实现自然语言意图路由以及结构化业务数据与非结构化文档的联合问答。
- 为工具定义输入参数、返回结构和异常处理逻辑，并通过来源引用展示知识库问答依据；建议进一步建立 `[N]` 道任务集，报告工具选择准确率和端到端任务成功率。
- 使用 YAML 管理模型参数和 Prompt，通过 Streamlit 实现流式输出、文件上传入库、会话记录与导出；补充演示 GIF 或 2–3 分钟演示视频，提高项目的可验证性。

“有效降低幻觉”“复杂意图识别”等结论应当由评测数据支撑。如果暂时没有评测结果，可以描述已经实现的机制，但不要直接宣称效果提升。

## 七、科研项目的推荐写法

建议将 FLRR 项目压缩为两条，并补充具体指标：

### 2025.09–至今｜FLRR：多分辨率图像聚类算法研究与实现｜第一负责人

- 面向混合分辨率图像直接 resize 导致信息损失的问题，提出连续函数低秩表示方法，构建结合稀疏降噪和谱聚类的低秩自表示模型，并推导 AO-ADMM 优化算法。
- 在 5 个公开数据集上完成 ACC、NMI、PUR 评测；相较最优基线平均提升 `[具体数值]`，在 `[分辨率/数据规模]` 下将运行时间或内存占用降低 `[具体数值]`。

如果不同数据集上的提升不一致，可以使用表格中的真实结果，选择最有代表性的平均提升或区间，不要为了简洁而写无法核验的“SOTA”。

## 八、项目仓库需要同步加强的内容

简历修改必须与 GitHub 仓库同步。建议每个核心项目至少具备：

- 清晰的项目定位和适用场景；
- 架构图以及上传、检索、生成数据流；
- 一条命令启动方式；
- `.env.example`；
- API 调用示例；
- 数据库表或数据模型说明；
- 固定评测集和可复现评测命令；
- 实际评测结果表；
- pytest 执行结果；
- 已知限制和后续优化；
- 2–3 分钟演示视频或 GIF；
- 不包含 API Key、个人隐私或无法公开的业务数据。

面试官查看项目时，应当能在三分钟内回答四个问题：

1. 这个项目解决什么业务问题？
2. 它与普通 RAG 教程有什么区别？
3. 你如何证明它的效果和稳定性？
4. 我怎样在本地复现？

## 九、修改优先级

### P0：投递前必须完成

- 修正尚未完成却写成已完成的项目描述；
- 将项目日期改为真实状态；
- 补充姓名、联系方式、求职意向、预计毕业时间和实习时间；
- 将技能按照后端、大模型应用、数据工程、机器学习分类；
- 修正“双一流专业”和“MCM 国际级二等奖”等不严谨表述。

### P1：显著提高面试率

- 完成 pgvector、多知识库、事务和重启恢复；
- 建立真实企业制度评测集；
- 填入 Recall、MRR、拒答率、延迟和测试数量；
- 为两个 AI 项目分别提供 GitHub 和演示视频；
- 压缩数学建模与科研描述，确保一页完成。

### P2：继续增强岗位竞争力

- 为 Agent 项目增加固定任务集和工具选择准确率；
- 实践 LangGraph 或明确的状态机工作流；
- 增加日志、Token 成本、延迟监控和失败重试；
- 了解 Redis、CI/CD、限流、降级和敏感信息保护；
- 根据不同 JD 调整关键词，而不是使用一份简历投递所有岗位。

## 十、最终定位

简历需要向招聘者传达的核心形象应当是：

> 具备扎实数学和机器学习基础，能够使用 Python/FastAPI 独立完成 RAG 与 Agent 应用开发，并能通过数据库设计、自动化测试、效果评测和容器化部署将大模型能力交付为可复现系统的硕士生。

现阶段最重要的不是继续增加第三个 AI 项目，而是把现有企业 RAG 后端真正做完、测出数字，并确保简历、README、代码和面试讲述保持一致。
