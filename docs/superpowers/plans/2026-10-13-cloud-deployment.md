# 低预算云端演示部署计划

目标：使用用户领取的腾讯云 Linux 试用服务器部署现有应用，完成上传、问答、日志和备份恢复验证，最后重建本地 Docker。

## 已确认的取舍

- 优先 0 元试用；可先尝试 2 核 2GB、Ubuntu 24.04 LTS x86_64，单人、小 PDF、CPU 推理。
- 已领取服务器：`162.14.71.180`，Ubuntu 24.04 LTS，用户 `ubuntu`。已通过 TAT 核对主机公钥，配置专用 SSH 密钥并验证登录；不代替用户购买或续费。
- 试用阶段仅通过 SSH 转发访问，Web 绑定服务器回环地址，数据库/API 不发布端口。HTTP 只存在于回环和容器网络，远程链路由 SSH 加密。
- 本轮不购买域名，不配置公网 Web 入口；公开上线与备案属于后续阶段，不能把 SSH 私有演示描述为已公开上线。
- 不合并项目、不引入集群或新数据库；保留原有业务与迁移。应用继续单 worker，生成并发设为 1，限制上传及容器内存。
- 先完成部署配置、CPU 镜像定义及可离线传输的模型准备；实际云端验收之后，才重建本地 Docker。准备期间不构建镜像、不重启现有服务。

## 执行任务

1. 增加独立云端 Compose：持久卷、重启策略、日志轮转、低内存参数、回环入口；为生成并发增加环境配置及测试。
2. Dockerfile 使用官方 CPU PyTorch 包，保留原有版本；实际构建时检查 CUDA 依赖不存在，避免沿用 8.7GB 镜像。
3. 提供部署工具：私有环境文件、配置检查、构建/启动、离线模型导入、二进制数据库备份和新数据库恢复。恢复禁止覆盖业务库，禁止自动删除数据库或数据卷。
4. 打包代码和指定 BGE 模型缓存，排除 `.env`、Git、用户数据、本地依赖及凭据；环境文件单独传输到已确认的用户服务器。
5. 等 SSH 信息后核对系统、磁盘、内存、Docker 和主机身份；2GB 实例按需增加 swap，已存在的 swap 不覆盖。
6. 云端构建、模型导入、迁移、启动，使用 SSH 转发验证注册、PDF、问答、来源、错误请求 ID 和历史。额外验证备份恢复，记录实际资源占用。
7. 云端验收完成后重建本地 API/Web，保留当前项目环境、数据库及卷，复验健康检查和请求 ID。

## 验收标准

- 所有业务和故障回归通过；云端数据跨服务重启保留。
- 云端只有 SSH 对指定客户端开放；Web 不直接暴露公网，数据库/API 无发布端口。
- 备份为有效 PostgreSQL custom dump，恢复到新库后核对表和向量数据；不以“文件已生成”代替恢复验收。
- 真实部署、配置检查、测试替身、实际模型问答分别记录。缺少服务器时只能报告部署准备完成。
- 禁止批量删除文件或目录，不清空数据库，不删除卷，不自动产生费用或提交/推送代码。
