因为 BERT 的训练方式和结构，本身就更偏向“**把整段文本看懂**”，而不是“接着往后生成”。

最核心的原因有两个：**双向上下文** + **每个 token 都能得到完整上下文后的表示**。

比如一句话：

```text
我今天去银行办理业务
```

理解“银行”这个词时，BERT 可以同时看左边和右边：

```text
左边：
我今天去

右边：
办理业务
```

所以它会形成一个结合整句话的“银行”表示。

这对下面这些任务特别合适。

### 1. 文本分类

比如：

```text
输入：
这个电影真的太好看了

输出：
正面评价
```

分类任务关心的是：

> 整句话整体表达了什么意思？

BERT 可以一次看到完整句子：

```text
这个电影真的太好看了
↑                  ↑
左边右边都能一起利用
```

然后通常使用 `[CLS]` token 的最终向量作为整句话的表示：

```text
[CLS] 这个电影真的太好看了
  ↓
Transformer Encoder
  ↓
[CLS] 的最终向量
  ↓
分类器
  ↓
正面 / 负面
```

所以 BERT 很自然地适合：

```text
情感分类
垃圾邮件分类
新闻分类
意图识别
```

因为这些任务都是：

> 给我整段文本，我判断它是什么。

---

### 2. 信息抽取

比如命名实体识别：

```text
马云出生在浙江杭州
```

希望模型识别：

```text
马云 → 人名
浙江杭州 → 地名
```

BERT 的输出不是只有一个向量，而是**每个 token 都有一个上下文向量**：

```text
马    → 向量
云    → 向量
出生  → 向量
浙江  → 向量
杭州  → 向量
```

而且“杭州”的向量已经参考了整句话。

于是可以直接在每个 token 后面接一个分类器：

```text
马   → B-PER
云   → I-PER
出生 → O
浙江 → B-LOC
杭州 → I-LOC
```

这就非常适合：

```text
命名实体识别
关键词抽取
关系抽取
槽位填充
```

因为这些任务本来就需要判断：

> 句子中的每个位置是什么。

---

### 3. 句子表示

比如你要判断：

```text
句子A：我喜欢人工智能
句子B：我对AI很感兴趣
```

是不是语义接近。

BERT 会把整个句子的上下文压进一个表示里：

```text
句子
↓
BERT
↓
一个向量
```

然后就可以比较两个向量。

所以它很适合：

```text
语义相似度
文本匹配
搜索
聚类
Embedding
```

这和你之前学 RAG 时的 Embedding 非常接近：都是希望得到一个**能够表示文本语义的向量**。

---

### 4. 为什么叫“理解型任务”

你可以把 BERT 和 GPT 对比着看。

BERT 更像：

```text
给我完整的一段话
↓
让我充分看懂它
↓
然后做判断
```

GPT 更像：

```text
给我前面的话
↓
根据前文
↓
预测后面应该出现什么
```

比如：

```text
苹果手机的价格很____
```

BERT 在预训练时预测“贵”时，可以同时看：

```text
左边：
苹果手机的价格很

右边：
后面的词
```

而 GPT 生成“贵”的时候只能看：

```text
苹果手机的价格很
```

不能偷看后面的内容。

所以从结构上：

```text
BERT：
左边 ← 当前词 → 右边
      都可以看

GPT：
前面的词 → 当前词
只能看左边
```

这就是为什么 BERT 更适合“理解”。

---

你可以把四种任务和 BERT 输出对应起来：

|任务|使用 BERT 的什么|
|---|---|
|文本分类|整句话的表示|
|信息抽取|每个 token 的表示|
|句子表示|整句话的语义向量|
|理解型任务|双向上下文信息|

所以真正核心不是“BERT 天生只能分类”，而是：

> **BERT 的 Encoder 会把完整上下文编码进每个 token 的表示里，因此特别适合那些“先把输入理解完整，再做判断”的任务。**

而 GPT 的 Decoder-only + Causal Mask 则天然适合：

> **根据已经出现的内容继续生成。**
