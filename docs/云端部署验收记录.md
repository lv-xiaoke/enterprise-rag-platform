# 云端演示部署验收（2026-10-13）

## 部署结果

- 腾讯云试用实例：Ubuntu 24.04、x86_64、2 核 2GB，沿用已有 1.9GB swap。
- 发布目录：`/home/ubuntu/rag-demo/releases/20261013-cloud1`，Compose 项目：`rag-cloud-demo`。
- Docker Engine 29.9.0 / Compose v5.6.0；迁移成功，PostgreSQL、API、Web 均健康。
- 这是 **SSH 私有演示**。Web 只绑定服务器 `127.0.0.1:8080`，API/数据库无宿主机发布端口；没有公网网站入口。

## 如何访问

本机 PowerShell 执行并保持终端运行：

```powershell
ssh -F "$env:USERPROFILE/.ssh/enterprise_rag_demo.config" -N -L 127.0.0.1:18080:127.0.0.1:8080 -o ExitOnForwardFailure=yes rag-demo
```

浏览器打开 `http://127.0.0.1:18080`，可注册自己的账号。若该端口已有本轮验收隧道，不必重复启动。

## 资源与工程检查

- 实际运行：`torch 2.13.0+cpu`、CUDA 为 `None`、NVIDIA 依赖包数量 0，构建时 `pip check` 通过。
- Docker 显示 API 镜像约 2.16GB、Web 94.6MB；原本本地 API 镜像为 8.71GB。
- 一次真实问答后的容器快照：API 约 619MiB、PostgreSQL 74MiB、Web 11MiB。该快照不是峰值或压力测试。
- 后端 64 项、前端 27 项测试及前端生产构建通过；已有 Starlette 弃用提示与前端大包提示仍存在。
- 独立只读代码审查未发现阻塞问题；实际部署另行完成上述验收。

## 运维与边界

- 操作命令见 [部署说明](../deploy/README.md)。云端命令需使用 `sudo`，环境文件权限为 600，私钥留在本机。
- Docker Hub 超时采用腾讯云官方内网加速；Debian/PyPI 使用已验证的腾讯镜像。CPU PyTorch 保持官方源，依赖版本未更改。
- 云端按单人演示配置：生成并发 1、上传上限 2MB。没有公开域名、备案、HTTPS 公网入口或多人负载验收。
- 本次验证了实际监听范围；腾讯云控制台的 SSH 来源白名单尚未读取核对。当前主机 UFW 未启用。
- 试用到期前另存备份；恢复工具只允许新建 `rag_restore_*` 库，不自动删除数据库、文件或卷。
